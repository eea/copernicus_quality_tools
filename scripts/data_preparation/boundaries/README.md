# Boundary resource preparation

These manual commands generate raster resources from explicitly supplied source
layers. They are separate from QC algorithms and do not register or publish a
boundary generation in QC Tool. Actual generation requires GDAL/OGR; layer
generation also invokes `gdalwarp`. CLI help works without those dependencies.

The output directory must already exist. Matching output files are replaced;
choose a separate working directory and review the generated resources before
using the application's boundary upload/publication workflow.

## Generate layers from a boundary mosaic

```bash
python3 -m scripts.data_preparation.boundaries.create_layers \
  --reference-dir /path/to/reference-masks \
  --mosaic /path/to/Boundary_EEA39_03035_020m.tif \
  --output-dir /path/to/preparation-output
```

`--reference-regex` defaults to `^mask_eea38uk_010m_`. The retained algorithm
selects only reference filenames ending in the EU tile code, takes the extent
from the reference raster and resolution from the source mosaic, then writes
compressed `mask_eea38uk_<resolution>_eu.tif` output. It does not generate all
tiles simply because the reference directory contains them. Sources must use
compatible grids/CRS; this command is a preparation utility, not a resource
validation suite.

## Generate per-feature SWF masks

```bash
python3 -m scripts.data_preparation.boundaries.create_masks \
  --source /path/to/projected-boundaries.shp \
  --output-dir /path/to/preparation-output \
  --pixel-size 5
```

The source must contain the historical `FID_eurobo` field and use the expected
projected metre-based CRS. The command rasterizes each feature onto an enlarged
grid and writes byte masks with NoData 0 and mask value 1, using DEFLATE
compression. Default pixel size is 5 metres.

The retained filename template is `mask_swf_005_<FID_eurobo>.tif` even when another
pixel size is supplied. Use the documented 5-metre workflow when preserving that
historical naming contract; changing the generation algorithm/naming belongs in
a separate reviewed data-preparation change.

Both commands preserve the existing rasterization/warp algorithms. Personal
machine paths have been replaced with explicit CLI inputs. No boundary datasets
are generated by the offline host tests.
