Quick start

Make your first request

  1. Create a named personal access token in Profile → Settings.
  2. Copy the token when it is shown. QC Tool stores only its digest and cannot display it again.
  3. Send it in the Authorization header over HTTPS. Never put a token in a URL or query string.
Request example 
curl --request GET \
  --url '{{ api_url }}/delivery-list?limit=20&offset=0' \
  --header 'Accept: application/json' \
  --header 'Authorization: Bearer <personal-access-token>'

Security model

Authentication and access

Every operational endpoint requires a named personal access token (PAT). The documentation page and OpenAPI schema are intentionally public and never ask for, transmit, or retain a token.

Permission snapshot

A new PAT captures the owner's permissions, roles, product grants, region grants, and administrator status at issuance.

Least privilege over time

Effective access is the intersection of that snapshot and current live access. Revocations apply immediately; later grants require a new PAT.

Independent lifecycle

You can keep multiple named PATs for different clients. Deleting one immediately revokes it and leaves the others active.

Treat every PAT like a password. Use HTTPS, keep it out of source control and logs, give each integration its own descriptive token, and delete tokens that are no longer used.

Response contract

Errors and safe usage

400Invalid JSON, field, identifier, product, or resource state
401Missing, malformed, revoked, or invalid bearer token
403Valid token without the required permission or object scope
404Delivery, job, product, or generated artifact is unavailable
413JSON body exceeds the 16 KiB endpoint limit
500An operation failed after validation; retry only when safe

Credential-scoped responses are marked private and non-cacheable. API authentication failures include a WWW-Authenticate: Bearer challenge. JSON errors use a stable code when one is available.
