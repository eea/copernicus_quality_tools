# QC Tool 3.0.0 installation record

## Schema and data handoff

Current Django models define the complete schema. Policy is `draft` with
`baselines: {}`. v3.0.0 ships no first-party migration packages, baseline
snapshots, legacy converter or released-migration execution logic. First migration
history belongs to a separately reviewed 3.0.1-or-later change.

`database apply` initializes an entirely empty target, including a new production
installation. A matching existing schema is a read-only no-op. A partial, foreign
or outdated schema is refused without reset or repair. Production startup runs
readiness checks; automatic initialization is development/test opt-in only.

Manual legacy conversion is outside the maintained codebase. The private handoff
contains a native PostgreSQL custom archive, checksum, provenance and validation
report. It restores the new schema and retained historical records without
converter code. No existing production or developer database is changed.

## Verification: 2026-10-13

Fresh models-only SQLite and PostgreSQL 14.24 probes passed, including empty
initialization, permissions/roles, synthetic record retention and read-only repeat
application. **48 database regression tests** passed on PostgreSQL; SQLite passed
43 with 5 PostgreSQL-only skips. Offline checks passed: 5 source-layout/policy,
14 QC evidence tooling and 109 JavaScript tests.

The private archive restored successfully into a new Unix-socket-only PostgreSQL
14.24 cluster. It matches the fresh current-model schema: **23 tables, 189
columns, 119 constraints, 91 indexes and 20 sequence definitions**, with no custom
triggers or migration recorder. CHECK expression comparison normalizes equivalent
PostgreSQL varchar/text cast rendering. All 23 tables' retained columns reconcile
with the reference copy; password comparisons use unusable state and datetime
comparisons respect `Europe/Prague` with `USE_TZ=False`. All 38 FK relationships
have zero orphans, identity sequences are safe, and filename history queries pass.

Production-mode `database plan|check|apply|check` passed on the restored copy with
PostgreSQL writes disabled; runtime hashes remained stable during those checks.
Readiness inspection itself has the documented required-contract limits.
The handoff has separate complete schema/data evidence and a checksum.

Docker Desktop became unavailable during a bounded test restore attempt. Native
isolated verification used the pinned Python 3.12.14 and Django 5.2.17 dependencies.
The wider native frontend suite collected **1,016 tests** per backend and exposed
two unchanged-source filesystem test errors: a macOS temporary-path alias and
upload concurrency. A canonical temporary path resolves the first; concurrent
upload locking remains unverified on native macOS. Supported Linux CI and packaged
image verification must be recorded separately; these native results do not
certify full application or worker correctness.

## Evidence boundaries

The converted copy combines September SQL storage/admin records, October delivery
and job exports and current web-export user metadata. It is **not a coherent
current production snapshot**. It retains 100 users, 57,996 deliveries, 61,732 jobs,
29,688 source locations, 196 admin events and 16,265 historical submission dates.
All user passwords are unusable and all storage credential references are blank.
The product catalog, product grants and verified publication receipts are empty.
Actual ZIPs, detailed QC reports and published folders are not reconstructed.

Stored QC statuses preserve reported historical observations. They do not prove
current-production reruns or v3 same-input acceptance parity. The only authorized
acceptance difference remains damaged ZIP handling. See the
[parity evidence guide](../../../../docs/development/legacy-qc-parity.md).

## Operator follow-up

Follow [manual PostgreSQL restore](../MANUAL_RESTORE.md) for a new empty target.
Provision authorized account passwords, product grants, unchanged original
specifications and private/shared storage. Verify allowed/denied access and the
full frontend/worker workflow before manually changing production traffic.

Current source tests with a dependency-runtime overlay do not certify packaged
images. Rebuild and verify the selected image pair and record immutable digests.
No deployment, registry publication or release tag is performed by preparing this
copy. Existing local services and production remain untouched.
